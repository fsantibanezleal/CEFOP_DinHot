# P07, Portable random generator

Physics component. Every random draw of the engine, the methods, the camera and the dynamics goes through one seeded generator
that the TypeScript live engine reproduces bit for bit. No global generator exists anywhere (ADR-0054).

| Item | Value |
|---|---|
| Module | `data-pipeline/pipeline/model/holo/core/rng.py` |
| Fixture | `tests/fixtures/rng-reference.json` |
| Tests | `tests/engine/test_rng.py` |
| Used by | everything that is random: M02, M03, the starts, the camera, the device flicker, the particle noise |

## Purpose

A run is a pure function of its parameters and its seed. For the browser to repeat what the pipeline baked, both sides must draw
the same numbers in the same order, which the standard library generators of Python and JavaScript do not do.

## Algorithm

`Rng` (line 41) is xoshiro128** seeded by four SplitMix32 outputs. Output $\operatorname{rotl}(s_1 \cdot 5, 7)\cdot 9$; update
$t = s_1 \ll 9;\ s_2 \mathrel{\oplus}= s_0;\ s_3 \mathrel{\oplus}= s_1;\ s_1 \mathrel{\oplus}= s_2;\ s_0 \mathrel{\oplus}= s_3;\
s_2 \mathrel{\oplus}= t;\ s_3 = \operatorname{rotl}(s_3, 11)$, with a state of four 32-bit words that must not be all zero.
SplitMix32 (the "improved" constants): $a \mathrel{+}= \texttt{0x9e3779b9}$; $t = a \oplus (a \gg 16)$; $t \mathrel{*}= \texttt{0x21f0aaad}$;
$t \mathrel{\oplus}= t \gg 15$; $t \mathrel{*}= \texttt{0x735a2d97}$; output $t \oplus (t \gg 15)$. The four state words are the first four
outputs for the seed.

- A uniform takes one 32-bit word: the top 24 bits over $2^{24}$ (exact in float32 and float64).
- A normal takes two uniforms (Box-Muller, $u_1 = 1 - \text{uniform}$ so that it lies in $(0, 1]$); the cosine value is returned
  first and the sine value is cached for the next call.
- Arrays are filled in C order by successive scalar draws. The draw order is part of the contract.

The TypeScript port reproduces the 32-bit stream and the uniforms exactly (integer arithmetic modulo $2^{32}$ and an exact
division by $2^{24}$); the normals use `log`, `cos` and `sin` of float64 and agree to about 1e-15.

## Implementation

- Entrypoint: `rng.Rng(seed)` with `next_u32`, `uniform`, `normal`, `uniform_array`, `normal_array`, `phases`. A seed is an
  integer in $[0, 2^{32})$; anything else is refused.
- The fixture `tests/fixtures/rng-reference.json` holds, for seed 20261028, 64 words, 64 uniforms and 64 normals, regenerated by
  running `tests/engine/test_rng.py` as a script. The reference seed of all fourteen cases is the same, 20261028.

## Acceptance criterion and test

The stream equals the committed fixture (`tests/engine/test_rng.py::test_matches_fixture_file`), equals an independent numpy
uint32 implementation (`::test_matches_independent_implementation`, 200 values), the uniform is the top 24 bits exactly
(`::test_uniform_is_top_24_bits_exact`), the moments are right (`::test_normal_moments_and_cache`) and a bad seed is refused
(`::test_bad_seed`).

## Measured values

Exact equality of integer words with the independent implementation (200 values) and with the fixture (64 words); no
tolerance is involved.

## Limits

- The generator is not cryptographic and the stream of one seed is short-range independent only in the usual statistical sense.
- The update rule in the module docstring was cross-checked by an independent implementation because the fetch of the reference
  C file returned a summary, not the verbatim text.
