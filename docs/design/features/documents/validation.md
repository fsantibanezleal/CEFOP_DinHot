# Adversarial validation: the documents: the executive view first, then the five pages

For each requirement of [`requirements.md`](requirements.md), the check that tries to break it: what was planted or refuted, and the test that plants it. `scripts/check_sdd.py` fails when a requirement has no row here (or two), when a check is empty, and when a gate names a test that does not exist. A planted row runs the requirement's own gate twice in child processes (`tests/adversarial/plant_run.py`): untouched, where it passes, and with the defect wrapped around the product's code, where it must fail.

| requirement | adversarial check | gate |
|---|---|---|

| DC-002 | a title of the honesty area is given an em-dash (written as an escape in the source): the rendered text holds it and the assertion fails (local-only: needs node and `npm ci` in frontend/, which the checks job does not install; the CI web job runs the same vitest suite) | `tests/adversarial/test_dinhot_documents_refuted.py::test_a_technical_view_with_an_em_dash_fails_the_typography_gate` |
| DC-003 | the range score counts the values outside the range instead of inside: the page disagrees with the bake and the assertion fails (local-only: needs node and `npm ci` in frontend/, which the checks job does not install; the CI web job runs the same vitest suite) | `tests/adversarial/test_dinhot_documents_refuted.py::test_a_range_scored_by_the_wrong_side_fails_the_experiments_gate` |
