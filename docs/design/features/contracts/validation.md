# Adversarial validation: contracts, providers and declared states (ADR-0080)

For each requirement of [`requirements.md`](requirements.md), the check that tries to break it: what was planted or refuted, and the test that plants it. `scripts/check_sdd.py` fails when a requirement has no row here (or two), when a check is empty, and when a gate names a test that does not exist. The guards themselves are attacked in `tests/adversarial/`; a planted row runs the requirement's own gate twice in child processes (`tests/adversarial/plant_run.py`), untouched and with the defect wrapped around the product's code.
