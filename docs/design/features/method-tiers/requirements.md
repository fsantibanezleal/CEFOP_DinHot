# Requirements: the method tiers and the manuscripts

EARS (Mavin et al., RE'09, doi:10.1109/RE.2009.9). Every requirement names the gate that fails when it is violated.
Every CAOS product implements three tiers of methods for its problem, none optional: the classical methods, the state of the
art and the product's own proposals beyond it, and it keeps a detailed technical report (and, for an interesting proposal, a
manuscript of its own) on Zenodo under a concept DOI (CAOS_MANAGE `conventions/method-tiers-and-manuscripts.md`, Felipe
2026-10-28). The template's own teaching example keeps `None claimed.` and no manuscript, and `.template-source` marks it as
the template; a product, which has no such file, is held to the whole rule. The guide is
[`docs/guides/09_method-tiers.md`](../../../guides/09_method-tiers.md).

| ID | Requirement | Gate |
|---|---|---|
| MT-001 | THE SDD's `## Method ladder` SHALL be a table of the columns id, tier, method, acceptance criterion and gate whose tier is `classical`, `sota` or `beyond`; WHEN the table or its tier column is missing (prose, a table without the column, a table inside a code fence), a tier is none of the three, an id is empty or repeated, or a method or criterion is empty or a placeholder, THE script `scripts/check_sdd.py` SHALL fail, saying how to add the column and naming the rule file, for the template as for a product. | `tests/test_method_tiers.py::test_adversarial_a_ladder_without_the_tier_column_fails_saying_how_to_add_it` (and `test_a_ladder_that_is_prose_fails_like_a_missing_column`, `test_adversarial_a_tier_that_is_not_one_of_the_three_fails`, `test_a_ladder_row_with_an_empty_method_or_a_repeated_id_fails`, `test_a_ladder_inside_a_code_fence_does_not_count`) |
| MT-002 | WHEN a product's method ladder has no method of the tier `classical`, `sota` or `beyond`, THE script `scripts/check_sdd.py` SHALL fail naming the missing tier and the rule file. | `tests/test_method_tiers.py::test_adversarial_a_product_without_a_method_in_a_tier_fails_naming_the_tier_and_the_rule` |
| MT-003 | WHEN a product's SDD has no section `## Beyond the state of the art`, says `None claimed.` in it (alone or next to a claim), or lists no proposed method `BS-<n>`, THE script `scripts/check_sdd.py` SHALL fail naming the rule file; WHEN a claim has no ladder row of tier `beyond` (a validation protocol alone is not a method beyond the state of the art) or a `beyond` row is no claim of the section, it SHALL fail naming the identifier. | `tests/test_method_tiers.py::test_adversarial_a_product_that_says_none_claimed_fails` (and `test_a_product_without_the_beyond_section_fails`, `test_a_product_with_no_claim_in_the_beyond_section_fails`, `test_none_claimed_next_to_a_claim_fails`, `test_adversarial_a_claim_with_only_a_validation_protocol_still_needs_a_beyond_method_row`, `test_adversarial_a_beyond_row_must_be_a_claim_of_the_section_and_a_claim_needs_its_row`) |
| MT-005 | WHEN a method of tier `sota` in the ladder is named by no level 3 notebook (`caos.methods`) in a language tree, a level 3 notebook names none, `caos.methods` names a method that is no `sota` row, is not a list, sits on a notebook of another level, or differs between the two languages, THE script `scripts/check_notebooks.py` SHALL fail naming the notebook or tree, the method and the rule file; WHEN the SDD has no readable ladder it SHALL leave that table to `scripts/check_sdd.py`. | `tests/test_method_tiers_notebooks.py::test_adversarial_a_sota_method_no_level_3_notebook_names_is_found_in_each_language` (and `test_adversarial_a_level_3_notebook_that_names_no_method_is_found`, `test_a_method_that_is_not_a_sota_row_of_the_ladder_is_found`, `test_methods_on_a_notebook_that_is_not_level_3_is_found`, `test_methods_must_be_a_list_of_strings`, `test_adversarial_the_two_languages_name_the_same_methods`) |
| MT-006 | WHEN a product's `product.json` has no `manuscripts` list or its list has no entry of kind `technical-report`, THE script `scripts/check_manuscripts.py` SHALL fail naming the rule file; WHILE the tree holds `.template-source` it SHALL accept an absent or empty list and still validate what is declared. | `tests/test_check_manuscripts.py::test_adversarial_a_product_without_the_field_fails_with_the_rule` (and `test_adversarial_a_product_with_an_empty_list_fails_with_the_rule`, `test_a_product_with_only_a_manuscript_fails_it_needs_a_report`, `test_adversarial_the_template_may_declare_no_manuscript`) |
| MT-007 | WHEN a manuscript entry has a `kind` outside `technical-report` and `manuscript`, a `concept_doi` that is not `10.5281/zenodo.<N>`, an empty or placeholder title or version, a technical-report version that is not `X.XX.XXX`, a `covers` that is not a list of `BS-<n>` or (for a manuscript) is empty, a claim the SDD does not list, a repeated concept DOI or an unknown field, THE script `scripts/check_manuscripts.py` SHALL fail naming the entry and the field. | `tests/test_check_manuscripts.py::test_adversarial_a_malformed_entry_fails_naming_the_field` (and `test_adversarial_a_manuscript_that_covers_a_claim_the_sdd_does_not_list_fails`, `test_a_repeated_concept_doi_fails`, `test_an_unknown_field_of_an_entry_fails`) |
| MT-008 | WHEN a technical report's version is ahead of `VERSION`, THE script `scripts/check_manuscripts.py` SHALL fail; WHEN it is run with `--release` and a technical report's version is not `VERSION`, it SHALL fail saying the report is published before or with a release that changes a method, a data source or a result. | `tests/test_check_manuscripts.py::test_adversarial_a_report_version_behind_the_release_passes_unless_the_release_changes_a_result` (and `test_a_report_version_ahead_of_the_release_fails`) |
| MT-009 | THE script `scripts/check_manuscripts.py` SHALL read nothing from the network unless run with `--zenodo`, and under `--zenodo` it SHALL fail a concept DOI with no Zenodo record, a record of another concept DOI and a latest Zenodo version that is not the declared one. | `tests/test_check_manuscripts.py::test_adversarial_the_default_run_never_touches_the_network` (and `test_adversarial_the_online_check_finds_a_version_behind_the_declared_one`, `test_the_online_check_finds_a_missing_record_and_a_different_concept_doi`) |
