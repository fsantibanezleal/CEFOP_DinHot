# I4 fragment: M07 against slmsuite's WGS-Kim (notebook review A, blocker B1)

## What changed

M07 (phase-fixed weighted GS, Kim et al. 2019) applied a weight update to the very first field. Kim's recursion has
$g_0 = 1$: the field of the start hologram is projected unweighted (iteration 1 is plain GS), and the first weight update
uses the field of iteration 2. slmsuite's WGS-Kim does the same (`_gs_farfield_routines`: `iter > 0`). Fixed in
`_gs.rule_wgs_fixed` (Python), `ruleWgsFixed` (TypeScript) and the WebGPU pass (`wgsl.ts`, mode 2, `k > 1`), and the engine
reference fixtures `live.M07`, `methods.M07` and `methods.M16` were regenerated (M16 calls the M07 rule).

Matched start (C03, 1024 traps, 30 iterations, `n_fix` 12, 4 seeds, same start phase, same DinHot metric, slmsuite at the
exponent 1 that M07 states), final relative standard deviation in percent:

| seed | M07 before | M07 after | slmsuite WGS-Kim (p = 1) |
|---|---|---|---|
| 20261028 | 0.329 | 0.1803 | 0.1803 |
| 20261029 | 0.491 | 0.1865 | 0.1865 |
| 20261030 | 0.231 | 0.3643 | 0.3643 |
| 20261031 | 0.500 | 0.3256 | 0.3255 |

After the fix M07 equals slmsuite to 1e-4 percent (4 of 4); the review's 4-of-4 gap is closed (cause and the one-change-at-a-time
table: the I4 report). The difference of definition that remains and is documented: slmsuite's default `feedback_exponent` is
0.8 (Leonardo's form), Kim and M07 use 1. At 0.8 the same code gives other numbers (0.2325, 0.2035, 0.1539, 0.1759), which
M07 also reproduces to 1e-4 once its update is skipped at k = 1; notebook 03-03 must call slmsuite with `feedback_exponent=1`
(or state the exponent) and pass the same start (`reset_phase(custom_phase=...)` and `init=`).

## For the main session (outside this unit's write scope; measured, not changed)

1. `pipeline/model/holo/learned/torch_forward.py:unrolled_wgs` (the B3 training loss) has the old rule (`g = g * mean_b / b` at
   every k). `tests/learned/test_torch_forward.py::test_unrolled_wgs_matches_m07` is its parity test against M07; torch is not in
   the pipeline venv, so the test is skipped there and was not run (UNVERIFIED), but it compares against M07's history and will
   fail once torch is present. The fix is one guard (`if k > 1:` on the `g` update); the B3 models in `models/` were trained on the old loss, so
   whether to retrain is the main session's decision.
2. `methods/optim/_gs_family.py:weighted_gs` is a second copy of the rule that the E3 tests use as "M07" (`variant="pfwgs"`): it
   updates the weights at k = 1 too and freezes the phase of the field at k = n_fix + 1 (M07: k = n_fix). B2, B4 (warm
   start) and B5 use it for their baselines and warm starts; `test_b1_device_wgs.py` and `test_b4_robust.py` score against it.
   Its numbers agree with M07 within the seed spread here (B4 p95: 6.268, 5.944, 6.092 against 6.192, 5.983, 6.068), so no claim moves.
3. `rule_gsw` (M06, Di Leonardo) updates at k = 1 as well; slmsuite's WGS-Leonardo does not. Not measured here.
4. Notebook 03-03 (and 03-04, which quotes M07) must be re-run on the corrected M07 and with slmsuite's exponent stated; the
   bake and the benchmark change for M07 (and M16) because the history of M07 changes.
