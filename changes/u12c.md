# U12c fragment: notebooks of topic 08 (learned holography), the notebook READMEs and the root README

Two notebooks per language, the same relative paths in `notebooks/en/` and `notebooks/es/`, topic `08-learned-holography`. Both run the
product's methods through the pipeline modules of `product.json` `method_entrypoints` (DinHot publishes no package) and finish in
under three minutes on the development machine. The row tests are `tests/notebooks/test_u12c.py`. The notebooks print no wall-clock
figure, because `scripts/run_notebooks.py --check` compares the committed bytes with a fresh run; the cost comparison of the first
notebook is printed as a boolean and the budgets are iteration counts.

## Findings for the main session

- **Topic 08 has no level 1 or level 2 notebook** (the levels assigned by the main session are 3 and 4), so `scripts/check_notebooks.py`
  reports "the topic has no level 1 notebook" and "no level 2 notebook" for it in both trees. It is the same open point as topic 04 of U12a.
  The topic needs a level 1 (what a released network is: the card, the ONNX graph, the baseline behind the slot) and a level 2, or the rule needs
  a waiver for topics that hold only the tiers' notebooks.
- The M17 acceptance in the SDD ladder says "hybrid at equal wall-clock reaches a higher accuracy than GS alone"; the notebook measures
  that the hybrid keeps the refinement on 0 of 8 volumes, so the hybrid is the network alone, and that the network is below M19 on the
  traps' own efficiency and uniformity. The criterion holds on the accuracy AC only.
- The record `data/derived/models/warmstart-model-rejected.json` carries its own control (`control_without_the_network`): random start,
  freeze 3, median 9.0 iterations, against the network start, freeze 3, median 16.5. The notebook reads it and re-runs the control on ten generated
  geometries (median 9.0, 40 percent never reaching one percent).
- `slmsuite` prints a timestamped INFO line for every `SpotHologram`; the second notebook disables logging at INFO level in its setup cell so
  the committed outputs are reproducible.
- `models/cgh-net.onnx` is read through `onnxruntime` by the method module; the first notebook lists it and its card in `caos.data`.
- **`scripts/run_notebooks.py --check` does not copy `models/`**: it copies only `data`, `data-pipeline`, `docs`, `content` and `notebooks` to
  the temp root, so the first notebook of topic 08, which reads the released graph `models/cgh-net.onnx`, falls back to the baseline in
  `--check` and fails with `KeyError: 'refine_kept'`. With `"models"` added to that tuple (one word, outside this unit's scope) all four
  notebooks of this unit pass `--check`; the runner was restored to its committed state afterwards. The amendment is proposed to the main session.
- **The READMEs of topics 05 to 07 are provisional**: U12b is not on the remote yet, so the index rows of its topics were written from its
  worktree's `changes/u12b.md` and folder listing at the time (07-06 `the-emulator-against-the-published-curves` was missing from the
  worktree at the last look). They must be reconciled with the final U12b fragment when it lands, in both `notebooks/en/README.md` and
  `notebooks/es/README.md`; `scripts/check_notebooks.py` then verifies every row.
